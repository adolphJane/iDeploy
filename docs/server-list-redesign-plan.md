# 服务器列表与连接流程重构方案

## 目标

让用户在服务器页面始终清楚三件事：当前选中了哪台服务器、连接卡在哪一步、下一步应该做什么。选择列表项本身不执行 SSH 或 Docker 命令。

## 当前功能定义

### 检测

当前“检测”会创建后台任务，并连续完成：

1. 使用 SSH 连接服务器。
2. 读取远端系统与架构信息。
3. 执行 `docker version` 检查 Docker daemon。
4. 把整段结果压缩成一个服务器状态。

问题是它把网络、主机指纹、身份认证和 Docker 环境混成一次检测，失败时只能显示模糊的“环境异常”。

### 凭据

当前“凭据”用于在 SSH Agent/私钥和账号密码之间切换。密码保存到 macOS 系统钥匙串，不保存到 SQLite。

问题是它属于低频配置，却和高频“检测”、危险“移除”一起挤在列表项中；保存凭据后也没有明确引导用户继续检测。

## 新的信息架构

### 顶部概况

- 服务器总数
- 已就绪数量
- 待处理数量

移除“Agent / 密码”概况卡。认证方式是单台服务器属性，不适合作为全局健康指标。

### 左侧服务器列表

列表只用于选择，不执行网络请求。每项展示：

- 名称和明确状态标签
- `用户@主机:端口`
- 当前认证方式：SSH Agent/私钥或密码
- 最近检测时间
- 一行可读的问题摘要
- 进入详情的箭头

移除列表项中的“检测、凭据、移除”三个文字按钮。整项可点击，并具有清晰的选中状态和键盘焦点。

### 右侧服务器详情

右侧改为两块内容：

1. **连接诊断**：网络 → 主机指纹 → SSH 认证 → Docker 环境。
2. **远程 Docker**：仅在 SSH 与 Docker 均正常时显示容器和刷新操作。

右上角只保留一个随状态变化的主操作：

| 当前状态 | 主操作 |
| --- | --- |
| 未检测、网络失败 | 检测连接 |
| 待确认主机指纹 | 核对主机指纹 |
| 认证失败 | 更新凭据 |
| SSH 正常、Docker 异常 | 重新检查 Docker |
| 全部正常 | 刷新容器 |

“编辑连接”“凭据设置”“移除服务器”放入右上角更多菜单；移除操作保持二次确认。

## 状态模型

后端检测结果应从单一状态拆成四个结构化步骤：

- `network`：未检测 / 检测中 / 可达 / 不可达
- `hostKey`：未确认 / 已信任 / 已变化
- `authentication`：未检测 / 已通过 / 失败
- `docker`：未检测 / 可用 / daemon 不可用

页面汇总状态使用：未检测、待确认指纹、需要凭据、无法连接、Docker 异常、已就绪。原始命令输出只进入可展开的技术详情，不直接作为列表摘要。

## 关键交互规则

1. 点击列表项只设置 `selectedServerID`，不执行任何远端命令。
2. “检测连接”按阶段执行，前一步失败后不继续执行 Docker。
3. 未通过 SSH 认证时，Docker 步骤显示“尚未检查”，不显示“刷新容器”。
4. 保存凭据后显示“保存并检测”主按钮；不自动发送密码或执行连接。
5. 主机指纹变化时阻断认证，并要求重新核对，不能自动覆盖。
6. 错误摘要使用用户可理解的文案；临时文件路径、`signal: killed` 等放入技术详情。
7. 检测和容器刷新均显示独立加载状态，避免整行看起来失去响应。

## 文案调整

- “检测”改为“检测连接”。
- “凭据”改为“凭据设置”。
- “环境异常”按原因改为“需要凭据”“Docker 异常”或“无法连接”。
- 页脚改为：“SSH 密码保存在 macOS 系统钥匙串；iDeploy 不保存明文密码或私钥。”

## 可访问性要求

- 状态同时使用图标和文字，不只依赖颜色。
- 列表项使用可聚焦按钮语义，并标记当前选中项。
- 异步状态通过 `aria-live` 通知。
- 主操作触控尺寸不低于 44×44 px。
- 错误技术详情支持选择和复制。
- 弹窗支持自动聚焦、Tab 循环与 Escape 关闭。

## 实施顺序

1. 重构列表项与右侧详情布局，移动操作入口并修正文案。
2. 增加结构化连接诊断结果，拆分网络、指纹、认证和 Docker 状态。
3. 将检测任务改为分阶段执行，前置步骤失败时停止后续命令。
4. 增加技术详情与错误映射，隐藏临时路径和底层噪声。
5. 补充前端状态测试、后端阶段测试和应用内交互复测。
