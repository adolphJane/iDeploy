# 发布后域名绑定与端口自动发现方案

状态：分阶段实施中。主域名/子域名资产、阿里云 DNS 记录管理、实际端口映射发现，以及已有 HTTP 端口映射上的受管 Caddy 入口应用与解绑已落地。现有 host 网络 Nginx 容器可选择受控 HTTP 路由模式，预览后备份、校验、重载并检查访问；此模式暂不自动签发或挂载 HTTPS 证书。自动分配端口、需要重建容器的绑定和发布端口变更联动仍按后续阶段实施。本文不执行实际服务器、DNS 或发布操作。

根据新增需求，域名管理以独立“域名”页面为主要入口，统一管理主域名、根域名访问项与子域名；部署页保留快捷绑定入口。完整页面与操作设计见[域名管理页面与整体交互方案](design-system/domain-management-page-plan.md)，本文描述其底层技术实现。

## 1. 目标与范围

用户可先在域名页管理主域名与子域名，发布成功后从域名页选择部署，或从部署详情选择已有域名。iDeploy 根据远端工作负载、实际端口映射和入口代理配置，生成可解释的访问方案；执行后展示域名、HTTPS、后端连接和 DNS 的实际状态。

首期覆盖通过 SSH 管理的 Linux Docker 主机、单容器，以及已经发布了 HTTP(S) 端口的 Compose 服务。一个部署可以绑定多个域名，每个域名指向一个明确服务端口。公网入口通常共用 80/443，不为每个域名单独分配公网端口。

首期接入阿里云云解析 DNS：授权后在应用内查询、手动新增、修改、启停和删除解析记录，明确提交后同步到阿里云。未接入 API 的域名保留外部手动配置与校验模式。暂不支持泛域名、路径分流、TCP/UDP 域名转发、负载均衡和多机入口。没有宿主机端口映射的 Compose 服务先返回具体配置指引，后续支持共享 Docker 网络接入。

主域名是资产分组，不固定到某台服务器；根域名和各子域名可以分别绑定不同部署与服务器。一个完整域名首期只有一个生效目标，迁移时才允许同一操作中的新旧入口临时共存。根域名不绑定、不解析，不妨碍独立子域名使用。

## 3. 用户流程与界面

增加独立“域名”页面，左列为主域名，右侧为主域名概况、包含固定 `@` 行的子域名访问表及操作记录。保持现有部署列表/详情布局，在部署详情中增加“域名与访问”卡片。复用 DeployStyle、SectionHeading、StateBadge、卡片和原生 Sheet；不增加固定的第四列。

1. 添加主域名只保存资产与固定根域名访问项，可继续添加子域名，不要求先发布或配置 DNS。
2. 从域名访问项选择部署，或从部署页选择主域名及 `@`/子域名；复用同一绑定表单。已有目标时进入明确的迁移流程。
3. 自动只读探测远端，展示目标服务、容器端口、实际宿主机端口、入口代理、DNS 与证书前提。
4. 唯一且验证可达的 HTTP 端点默认选中；多个候选端点通过 Picker 选择，并展示推荐理由。允许手动选择该部署已发现的端口。
5. 预览展示实际执行内容，例如“新增 app.example.com → 本机 18080 → 容器 3000；初始化受管入口；申请证书”。涉及容器重建时明确提示影响及恢复方案。
6. DNS 未就绪时提供 A/AAAA/CNAME 建议；阿里云模式可编辑并预览记录，在应用内明确提交，API 回读后再检查公开解析。外部手动模式保留复制指引。绑定与 DNS 变更分别记录阶段，不能将 API 保存成功等同于公网已生效。
7. 成功后显示访问链接、复制、检查、编辑和解除绑定。解除绑定保留域名资产与应用；移除域名资产是独立操作，有子域名、绑定或未完成任务时阻止直接删除主域名。

域名字段只接受主机名：规范化大小写、尾部点和 IDNA；拒绝协议、端口、路径、换行、泛域名及配置片段。主域名归属使用公共后缀规则识别，完整域名资产全局唯一；不同入口的同域名变更通过迁移操作处理。

分别显示 DNS、代理、TLS、后端和最近检测时间，不能用一个“成功”掩盖部分失败。配置重载成功不等于证书已签发，也不等于公网可访问。

## 4. 自动发现与端口推荐

### 4.1 数据采集

- 根据 deployment 的服务器和明确工作负载身份匹配容器，不按镜像名猜测目标。
- 读取 Docker inspect 的实际端口绑定、HostIp、容器声明端口、网络模式和 Compose service 标签；仅提取必要字段，不保存完整 inspect 和环境变量。
- 检查宿主机 TCP/UDP、IPv4/IPv6 监听及可识别的占用者；能力或权限不足时返回 unknown，不能返回 available。
- 检查受管代理配置、80/443 与管理端口、Docker 模式、挂载和配置哈希；识别现有 Nginx/Caddy/面板入口，但不自动遍历和导入所有配置。
- 在与代理相同的网络环境验证候选后端；携带目标 Host，分别识别 HTTP/HTTPS。不能仅凭常见端口认定 Web 服务，HTTPS 上游不得默认跳过证书验证。
- 采集结果带 observedAt、来源与限制；缓存只用于展示，执行前必须重新探测。

### 4.2 推荐优先级

| 优先级 | 依据 | 行为 |
| --- | --- | --- |
| 1 | 已生效的域名目标仍存在且可达 | 保持原配置，避免每次发布换端口 |
| 2 | 运行容器的实际宿主机映射，已验证 HTTP(S) | 优先复用；无需重新发布 |
| 3 | 多个服务或多个 Web 端口 | 显示服务名、映射和探测结果，要求用户明确目标 |
| 4 | 配置、Compose 渲染结果或镜像 EXPOSE 声明 | 生成候选；验证后才能用于绑定 |
| 5 | 无映射但单容器内部端口已明确 | 生成端口分配及重建计划，等待执行该计划 |
| 6 | 只有框架默认端口或信息不足 | 仅作提示，要求补充；不自动绑定 |

HTTP 401/403/404 可以证明收到 HTTP 响应，但不代表业务健康；健康检查路径和成功条件独立配置。数据库和纯 UDP 端口不作为 Web 域名候选。

例：检测到 `0.0.0.0:18080 -> 3000/tcp` 且 HTTP 可达，推荐直接代理到 `127.0.0.1:18080`。若映射只绑定特定网卡，则使用经验证可达的该主机地址，不能一律改写为 localhost。后续可单独建议收窄公网暴露，不能在绑定时静默修改已有映射。

### 4.3 需要新增主机端口时

- 建议默认候选区间为 18080–18999，服务器级可配置；排除监听、Docker 发布、有效预留和系统临时端口范围，范围耗尽时要求配置，不能越界猜测。
- 新增的受管单容器后端优先使用 `127.0.0.1:候选端口:容器端口`；容器内服务仍需监听容器可达地址。
- 分配与应用使用现有 `server:<id>` Job 锁，配合数据库预留和远端互斥；外部进程仍可能抢占，最终以 Docker 实际绑定为准。
- 执行前再次检查；仅在尚未应用路由且可安全恢复的阶段有限重试，成功后记录并稳定复用实际端口。
- 端口不能通过修改 SQLite 立即生效。已有单容器需要使用固定 Digest 重建；Compose 需要明确修改并重新应用其配置，首期不自动改写源码。

## 5. 服务器统一入口

建议首期采用每台服务器一个 iDeploy 受管 Caddy，承载多个域名，利用其自动证书申请、续期和配置重载能力。统一封装入口驱动，后续再增加现有 Nginx/Caddy 的受控接入。

首期拓扑明确为 Linux Docker 主机上使用 host 网络的受管 Caddy 容器，因此代理可以访问宿主机 localhost 后端。不能在普通 bridge 容器中直接使用 `127.0.0.1:主机端口` 指向宿主机。镜像使用验证过的固定版本/Digest，代理自动重启，配置和证书数据持久化。

入口分为三种探测结果：

| 状态 | 处理 |
| --- | --- |
| 已有 iDeploy 受管入口且配置一致 | 合并新增路由，校验完整配置后重载 |
| 没有入口且必要端口可用 | 在应用计划中包含初始化步骤 |
| 其他 Nginx/Caddy/宝塔等占用入口，或受管配置漂移 | 阻止自动接管；展示占用者、诊断和可复制的配置指引 |

代理管理接口仅监听本机，通过 SSH 使用，检测管理端口冲突，不对公网开放。只管理带明确归属的资源和目录，不覆盖外部配置；同服务器的所有域名合并为完整配置后校验，不能让一个错误域名破坏其他站点。

受管目录保存当前配置、候选配置、上一可用版本和操作回执，使用内容哈希及预期版本检测漂移。读取实际状态后才能覆盖；启动时发现同名但无归属标识的资源须报冲突。

## 6. DNS、HTTPS 与可达性

- 阿里云接入使用受限 RAM 身份，AccessKey 存于 macOS Keychain，SQLite 只保存凭据引用。首次创建授权可能需要阿里云控制台，授权后日常解析配置在应用内完成；域名在阿里云注册并不保证其权威 DNS 由阿里云托管，连接时同时核对 zone 与实际 NS。
- DNS 记录操作保存阿里云 RecordId、明确的记录字段和变更前值；编辑前重新读取，检测外部修改。调用超时先对账再重试，避免重复新增；只管理用户选中或本次创建的记录，不批量覆盖整域配置。
- 查询阿里云记录与公开 DNS 解析分开显示：API 保存成功显示“已提交，等待解析生效”，后续验证通过才显示访问就绪。绑定失败不自动反向覆盖可能已被外部修改的 DNS；恢复方案列出实际变更及冲突。
- DNS 目标地址作为服务器入口配置独立保存。SSH 地址可能是内网、跳板或 NAT 地址，不能直接当作公网解析目标。
- 校验 A/AAAA/CNAME，列出解析结果及预期入口。AAAA 指向不可达服务器需明确提示；CDN 和负载均衡场景不能仅靠 IP 相等判断正确。
- 首期默认公网证书验证方案要求正确 DNS 和 80/443 外部可达；提供端口、防火墙、安全组、NAT 和证书失败的分项诊断。通配符及 DNS challenge 后续实现。
- 区分服务器本地后端探测、客户端直连入口（指定 Host/SNI）、正常 DNS 的端到端访问；记录探测位置。本地失败也可能源于客户端网络，不能断言全球不可达。
- 先检查待签发条件，再应用配置；证书签发异步等待并设置超时，允许重试，不在每次刷新时重新申请证书。
- 客户端 SSH/DNS 凭据仍使用 macOS Keychain。自动签发的 TLS 私钥由远端代理保存在权限受限的持久化存储中，不回传、不写 SQLite 或日志；这与本地连接凭据分开管理。

## 7. 数据模型和跨层接口

新增迁移，旧部署保留原端口和发布记录，升级后不自动创建入口或绑定。

| 实体 | 建议保存的核心字段 |
| --- | --- |
| `domains` | 规范化主域名、显示名称、备注、DNS 管理模式；主域名不要求关联服务器 |
| DNS Provider 连接及记录变更 | 阿里云连接 ID、Keychain 引用、zone 标识、RecordId、记录前后值、Job/请求回执和应用状态；不存 AccessKey 明文 |
| `domain_hosts` | 主域名 ID、主机标签（根域名为 `@`）、规范化完整域名、备注；完整域名全局唯一 |
| `server_ingresses` | server_id、入口驱动/模式、预期公网地址、端口区间、受管资源标识、desired/applied revision、配置哈希 |
| `deployment_domain_bindings` | domain_host_id、期望/已应用 deployment_id 与 ingress_id、Compose service、容器目标端口、上游协议、期望/已应用版本及迁移操作关联；一个访问项只有一份当前配置 |
| `ingress_operations` | Job、幂等键、计划及基准版本、操作阶段、前后配置引用、完成结果、恢复结果 |
| `server_port_reservations` | 服务器、监听地址、端口、协议、部署归属、状态及过期信息；检查通配地址与特定地址的冲突 |
| 运行观察结果 | 实际后端、DNS/TLS/路由/后端状态、观测时间、错误及配置漂移 |

端口和路由相关发布快照只保存非秘密配置；同时关联入口操作版本。域名绑定独立于镜像版本，普通镜像回滚保留当前域名；历史路由配置通过独立操作恢复。回滚后重新发现实际端点，后端不匹配时给出修复计划，不能继续显示访问正常。

主域名和子域名 CRUD、只读 DNS 查询接口见页面方案；绑定相关建议新增 Go 接口：

| 接口 | 语义 |
| --- | --- |
| `InspectServerIngress` | 只读检查入口、能力、占用与管理归属 |
| `DiscoverDeploymentEndpoints` | 返回结构化候选端点、验证结果与推荐理由 |
| `PlanDomainBinding` | 以域名访问项 ID 和部署 ID 只读生成目标、DNS 指引、变更与重建影响，返回有有效期的计划 |
| `ApplyDomainBinding` | 验证计划版本并入队；过期或状态变化返回需要重新规划 |
| `ListDeploymentDomains` / `InspectDomainBinding` | 查询配置及新鲜的分项状态 |
| `RemoveDomainBinding` | 入队移除该路由，成功后再完成本地解绑；保留域名资产 |

业务规则置于 Go Runtime，原生界面只展示与调用；同步维护 `systemservice.go`、`native_call.go`、`NativeBridge.swift` 调用、CLI 和 MCP schema/控制通道。CLI/MCP 的写操作沿用现有确认及异步 Job 语义，不绕过其边界。

## 8. Job、失败恢复与发布衔接

绑定任务使用同服务器 Job 锁，阶段为：重新探测 → 校验计划版本 → 必要时准备/重建后端 → 生成整份代理候选配置 → validate → 原子替换配置并 reload → 核对代理实际版本 → 必要时执行明确授权的 DNS 变更并回读 → 检查公开解析/TLS/访问 → 记录应用结果。DNS 记录变更另按 Provider/域名串行；组合操作预先确定锁顺序并校验双方版本，避免跨服务器迁移互相覆盖。

文件替换与远端重载、SQLite 更新无法构成一个事务。每个副作用前后保存操作阶段和回执；重试以 operation ID、配置版本和实际哈希判断是否已完成，避免重复初始化和重复签发。应用重启、SSH 中断或取消后先对账，再决定继续、恢复或标记需要处理。

- 单独绑定失败不改变既有成功发布记录；绑定使用独立 Job 和状态。
- 配置校验或重载失败保留/恢复上一份完整配置；涉及其他域名时同样验证其路由未被破坏。
- 首次绑定证书等待超时，显示“证书待就绪/失败”，保留已知的实际配置状态，不谎报全部未生效；后续可重试或解绑。
- 新增绑定涉及后端重建时，进入制品复用的部署流程，并记录实际端口快照；代理切换成功前不能清理旧容器备份，失败时恢复端口、容器与代理配置。
- 后续普通发布保持后端端口；用户修改端口时生成联合计划。制品健康、路由切换和收尾阶段分别记录，恢复失败明确显示需要人工处理。
- 删除部署/服务器前处理域名和入口资源；有绑定时禁止仅级联删除本地记录而留下失管路由。共享代理不随单个部署删除。
- 桌面退出后远端代理与自动续期继续运行；状态检查仅在刷新或后台核心运行时执行，首期不承诺常驻监控告警。

## 9. 实施顺序与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| P1：资产、发现与规划 | 主域名/子域名迁移与管理页、只读 DNS 检测、结构化端口检查、入口探测、规划接口和预览 | 主域名与独立子域名正确分组；识别 Docker/宿主机占用、IPv6、多服务、无权限和过期缓存；唯一候选有推荐理由 |
| P2：最小可用闭环 | 阿里云连接与应用内解析记录编辑、域名页/部署页共用绑定表单、单容器与已有映射的 Compose 绑定、受管 Caddy、HTTPS、解绑和 Job 恢复 | 记录同步可回读、外部变更可识别；根域名/子域名可独立绑定不同服务器；同部署多域名复用后端 |
| P3：发布联动 | 自动端口分配、固定制品重建、发布配置快照及联合恢复 | 竞争抢占、变更中断、回滚和漂移场景恢复一致；普通发布保持访问地址 |
| P4：扩展接入 | 现有 Nginx/Caddy 受控接入、其他 DNS Provider、共享网络与高级路由 | 接入范围可审计，凭据隔离，不覆盖外部配置 |

P2 可先上线“复用已有端口绑定域名”，P3 再完成“缺少映射时自动规划并应用端口”的完整体验。自动解析和推荐从 P1 即具备。

验证包括相关 Go 单元测试、迁移兼容测试，以及隔离 Linux Docker 环境中的端到端测试：重复执行、入口冲突、多域名、Compose 多服务、DNS 未就绪、证书失败、重载失败、SSH 中断和回滚。证书集成验证使用 ACME staging，避免反复消耗生产签发额度。

跨模块实现完成后运行 `go test -tags native ./...`；原生桥接/界面改动运行 `bash build/darwin/build-native.sh build`。界面验证最小窗口、键盘焦点、鼠标与 VoiceOver，沿用当前单页方案确认流程。本文是规划文档，未执行这些构建、测试或远端验证。

## 10. 技术依据

- [阿里云 DNS API](https://help.aliyun.com/zh/dns/api-alidns-2015-01-09-overview)：解析记录查询、新增、修改、启停与删除。
- [阿里云自定义权限策略](https://help.aliyun.com/zh/dns/alibaba-cloud-dns-custom-permission-policy-reference-dns)：按域名限定写权限，查询类权限依据具体接口分别授权。
- [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https)：自动证书、续期及验证前提。
- [Caddy CLI](https://caddyserver.com/docs/command-line)：配置 validate 和 reload。
- [Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)：宿主机绑定地址与访问范围。
- [Docker host 网络](https://docs.docker.com/engine/network/drivers/host/)：Linux host 网络下的代理与宿主机连通语义。
