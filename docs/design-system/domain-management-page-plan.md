# 域名管理页面与整体交互方案

状态：分阶段实施中。当前 SwiftUI 页面已支持主域名/子域名资产、阿里云及 Cloudflare DNS 连接与记录编辑、外部手动配置、绑定草稿、端口映射发现、已有 HTTP 映射的受管入口应用/解绑及本机 DNS/HTTPS 检查；自动端口分配和发布联动仍待后续阶段。本文保留完整交互目标。

绑定预检新增“使用现有入口代理（Nginx）”模式。当前仅接入运行中的 host 网络 Nginx 容器，且 `/etc/nginx/nginx.conf` 必须是可由 SSH 用户写入的宿主机文件挂载；多个候选、无可维护挂载、已有同名路由或配置漂移时停止自动写入。预览展示将加入主配置 `http` 区块的 iDeploy 路由。应用任务在原文件保持同一 inode 的前提下备份、写入、执行 `nginx -t`、重载并验证 HTTP 路由，失败时尝试恢复备份。此模式只新增 HTTP 反向代理，不自动签发或挂载 HTTPS 证书；任务结束会分别报告 DNS、HTTPS 与后端检查结果，HTTPS 未就绪时不得显示为可访问。解除绑定只移除 iDeploy 标记区块中的路由。

本方案将[发布后域名绑定方案](../domain-binding-plan.md)扩展为独立的域名管理能力。域名页负责域名资产和访问管理，部署页保留快捷绑定入口，两处共享同一份配置、状态和操作流程。

当前 DNS 配置支持选择阿里云云解析、Cloudflare 和外部手动配置；连接凭据保存在本机 Keychain。阿里云使用 RAM AccessKey；Cloudflare 使用限定 Zone 的 API Token。主域名页已读取的记录可逐行点击“编辑”，表单以远端最新记录为基准，保存后直接提交给所选服务商并重新读取列表；服务商处记录已经改变时阻止覆盖。Cloudflare 暂不提供记录启停操作。选择连接不等于已切换权威 NS，页面须明确提示核对实际 DNS 托管方。

保存服务商连接与关联主域名是两步操作。主域名未关联时显示“连接 DNS”，并提示已有连接数量；DNS 配置可预选唯一已保存的连接，但只有点击“保存并读取解析”才持久化关联。配置内新增连接后自动选中新增项，返回主域名页后读取远端记录。未关联时解析管理入口禁用，不能把未请求状态显示成零条记录。

域名页使用顶部唯一的“刷新数据”入口及 ⌘R，刷新当前主域名的本地访问项和服务商记录；后台十秒轮询只刷新本地元数据，不反复请求云端 DNS。记录区域显示数量与精确到秒的上次成功读取时间；读取失败显示可复制错误，保留上次成功数据和时间。当前域名页及表单使用完整浅色环境并显式指定正文色，避免深色系统外观下出现浅底白字和不可见的筛选项。

当前服务绑定以 DNS 完整域名为入口：读取到的 A、AAAA、CNAME 自动出现在“域名访问”，同名的多地址、多线路记录合并为一个绑定项，并按完整域名匹配已有草稿或已应用配置。用户可从解析记录行或访问列表直接点“服务绑定”，无需先在本地创建同名子域名。仅在进入绑定流程时按需持久化访问项，重复进入会复用原 ID、备注和绑定；读取 DNS 本身不批量导入数据库。TXT、MX、通配符及无效主机名不提供网站服务绑定，并说明原因。读取失败、记录删除或改名后，已有本地绑定仍保留并提示核对 DNS，不跟随远端记录自动删除或迁移。域名概况的服务商卡片只描述 DNS 连接，服务绑定状态在域名访问区显示。

右侧列表以同一套自适应行组件展示：宽窗口中按“记录类型 / 主机记录 / 完整域名 / 解析值与 TTL / 状态 / 操作”分栏；主机记录直接显示值，不在每行重复显示字段名。窄窗口先展示类型、主机记录和完整域名，再展示解析值、状态和操作；域名访问行按“域名来源 / 部署与端口 / 状态 / 操作”对应排列。类型使用现有标签组件，启用、未绑定、草稿、已应用与失败使用文字状态徽标；访问行固定更多菜单位置以对齐操作列。标题与筛选空间不足时上下排列，长域名和解析值可选取复制并通过悬停查看全文。右上 DNS 概况仅保留 DNS 配置，解析管理入口集中在记录卡片。组件位于 `macos/Sources/DomainListRows.swift`，含宽、窄及长内容 Preview；业务调用仍由原页面负责。

本次列表布局验证：原生构建及应用打包通过；实际应用检查宽窗口、解析编辑入口、绑定筛选和 Tab/Escape；使用相同组件的独立 360pt 预览检查长域名、IPv6、CNAME 值、已应用及草稿状态。未完成完整 VoiceOver、深色模式和提高对比度验收。

服务绑定入口已统一在 DNS 记录行，下方不再重复展示同一批域名的访问列表。记录行同步呈现已配置服务、容器端口和草稿/已应用/失败状态；已有配置的操作显示为“管理绑定”。每条记录的更多菜单统一提供复制域名和解析值；已存在本地非根域名访问项时额外提供编辑访问备注。完整解析管理弹窗同样读取绑定状态，以覆盖超过首页预览条数的记录。仅未匹配到当前 DNS 的手动访问项或已有绑定保留在“其他访问项”；无 DNS 连接时保留手动绑定列表。查询错误保留可复制提示及已有数据，移除重复列表不删除本地资产或更改远端入口。

## 1. 对象关系与命名

界面使用“主域名”“子域名”，对应本次需求中的一级、二级域名。例如主域名 `example.com`，子域名 `api.example.com`。这是产品分组命名，不要求用户理解 DNS 的技术层级。

| 对象 | 例子 | 交互规则 |
| --- | --- | --- |
| 主域名 | `example.com` | 顶层管理分组，保存备注、DNS 托管信息及所属域名清单，不绑定到固定服务器 |
| 根域名访问项 | `@`，完整域名 `example.com` | 主域名详情内的固定行，可独立绑定部署；未绑定不影响子域名 |
| 子域名访问项 | `www.example.com`、`api.example.com` | 由主域名和主机名前缀组成，各自管理 DNS、部署、HTTPS 和访问状态 |
| 部署绑定 | `api.example.com → API 部署 → 服务器 B → 服务端口` | 目标服务器随部署确定；首期每个完整域名只有一个生效目标，一个部署可以绑定多个完整域名 |
| DNS 记录 | `api / A / 预期入口 IP` | 区分“建议填写值”和“实际查询值”；本地保存不代表 DNS 已修改 |

主域名可以不提供网站：`@` 保持未绑定，只有 `api`、`console` 等子域名对外服务。子域名不继承根域名的服务器、应用端口或证书配置，也不默认 CNAME 到根域名。

新增主域名使用公共后缀规则识别可注册部分，支持 `example.co.uk`，不能简单截取最后两段。输入 `api.example.com` 时展示归属预览并引导添加到 `example.com` 下。国际化域名规范化保存，显示原始可读名称与可复制的 ASCII 值；拒绝协议、路径、端口、公共后缀本身和泛域名。手工新增子域名表单支持单个主机标签，如 `api`、`www`；从 DNS 记录绑定可识别 `api.dev` 等多段主机名。独立委派 DNS zone 留待扩展。

添加主域名只建立本地管理记录，不注册或购买域名、不修改 NS，也不代表已验证所有权。读取到 NS 仅说明解析托管信息，不代表 iDeploy 获得写权限。

## 2. 页面入口与布局

全局侧栏在“服务器”之后增加“域名”，沿用当前深绿导航、浅绿画布和列表/详情结构。主域名列表宽度沿用现有约 240–330pt；不额外引入第四个固定分栏，也不改造其他页面导航。

### 左侧：主域名列表

- 标题“域名”，显示主域名数量；右侧 `+` 添加主域名。
- 搜索同时匹配主域名、子域名和备注；匹配子域名时保留其父分组，并在选中后定位右侧对应行。
- 每行显示主域名、子域名数量、已绑定数量；有异常时显示文字和数量，不能仅用颜色。
- 默认按主域名排序，保留当前选择；可筛选“全部 / 有异常”。未绑定域名不自动计为异常。

### 右侧：选中主域名详情

内容按以下顺序展示，使用 PageContainer、SectionHeading、StateBadge、原生按钮和现有卡片：

1. **标题及操作**：完整主域名、备注；连接服务商后从 DNS 记录发起绑定，手工添加访问域名保留在菜单中，供未配置 DNS 的域名使用；菜单保留“编辑资料”“移除主域名”。
2. **域名概况**：管理模式（阿里云 API / 外部手动配置）、连接权限、已查询的权威 NS、已绑定数量、需处理数量和最近检查时间。首次未检查显示“尚未检查”。
3. **绑定操作与状态**：直接附于 DNS 记录行，按完整域名匹配同一绑定；下方仅列未匹配当前 DNS 的其他访问项，已有绑定不会因远端记录缺失而消失。
4. **近期操作**：当前主域名下的绑定、迁移、解绑和检测结果，标明具体完整域名及任务入口。

域名访问表的必要列：

| 列 | 内容 |
| --- | --- |
| 域名 | 根域名标为 `@ · example.com`；子域名显示完整名称，可复制 |
| 绑定目标 | 项目/部署名称及服务器；未绑定显示“未绑定部署” |
| 访问状态 | 当前最需处理的状态及下一步，例如“DNS 待配置”“证书申请中”“可访问” |
| 操作 | 未绑定为“绑定部署”，已绑定为“管理访问”；更多菜单提供复制和移除等操作 |

单击行打开“域名详情”原生 Sheet，提供基本信息、DNS、部署绑定、HTTPS 和最近任务的完整内容。小窗口下减少表内次要信息，完整信息始终能从该 Sheet 获取；不堆叠多个模态窗口，绑定表单在同一个 Sheet 内切换内容，返回时保留输入。

## 3. 主域名与子域名的新增流程

### 3.1 添加主域名

1. 点击列表 `+`，选择“从阿里云导入”或填写主域名与可选备注；导入时选择已授权连接和明确的域名，填写模式可使用外部手动配置。
2. 输入时规范化并检查重复，展示将管理的主域名。误填子域名时说明归属，并提供转入该主域名下的操作。
3. 点击“添加”只保存本地资产，不要求先连服务器或配置 DNS；网络查询失败不阻止本地添加。连接阿里云只读取记录，不自动接管或改写已有解析。
4. 选中新主域名，展示固定 `@` 行及子域名空态，提示“绑定根域名”或“添加子域名”。添加成功后按需异步查询 NS，并将失败留在概况卡片内。

空态说明应为“添加已有域名后，可管理子域名并绑定部署”。不出现购买、注册或 NS 托管成功等承诺。

### 3.2 添加子域名

1. 在主域名详情点击“添加子域名”，填写前缀，例如 `api`，旁边固定显示 `.example.com`，实时预览完整域名。
2. 可选填写备注；校验前缀、IDNA 和完整名称唯一性。输入 `@` 时引导使用已有根域名行；粘贴完整域名时仅在归属一致时提取前缀并展示结果，不重复拼接。
3. 点击“添加”保存访问项，定位该行并打开域名详情；其主操作为“绑定部署”。
4. 添加子域名不会自动创建解析记录，也不会默认把 `www` 与根域名绑定为同一站点。

主域名、子域名名称创建后不直接重命名；资料编辑只改备注等元数据。需要更换名称时新增访问项并走迁移，避免界面改名导致旧 DNS 和路由遗留。

### 3.3 接入阿里云与应用内配置解析

“连接阿里云”表单填写连接名称、AccessKey ID 和 AccessKey Secret，保存于 macOS Keychain；测试连接后分别展示查询能力、写权限状态和可访问的域名。只读测试不能宣称拥有写权限，权限不足不通过创建测试记录来验证。首次授权可提供阿里云 RAM 设置指引，日常操作不再要求打开官网。

连接后，在主域名详情提供“解析记录”入口，打开原生 Sheet：查询并展示完整的远端记录列表，首期编辑器覆盖 A、AAAA、CNAME 和常用 TXT；其他类型显示为只读，已有邮件等记录保持原样。支持按主机记录/类型搜索，用户明确选择单条记录后修改、启停或删除；不因导入域名自动修改任何记录。

点击“添加解析”填写主机记录、记录类型、记录值、TTL 和解析线路；`@` 对应根域名，`api` 对应子域名。默认值按阿里云当前接口和域名套餐能力获取、验证，不硬编码不支持的 TTL 或线路。记录值按类型校验，A/AAAA 不填写端口。

提交前展示新增/修改差异；“保存到阿里云”才真正调用 API，成功后回读并显示“已提交，等待解析生效”。公开 DNS 生效状态单独检测。编辑时保留 RecordId，提交前回读校验外部变更；不全量覆盖记录集。删除记录、切换指向等操作明确展示受影响的完整域名与值。

“解析记录管理”和“绑定部署”相互独立：用户可以只配置 DNS，也可以在绑定流程中直接使用服务器推荐值。解绑部署不自动删除阿里云记录；可在解析记录列表独立删除。首期不提供 NS 托管迁移或域名注册操作。

## 4. 统一的绑定交互

域名页和部署页复用同一流程；界面采用有返回按钮的分段表单，沿用原生 Sheet，不采用移动端全屏向导。

### 第一步：选择目标

- 从域名页进入：完整域名固定，选择部署。选项显示项目、工作负载、服务器和运行状态，支持搜索。
- 从部署页进入：部署固定，先选主域名，再选根域名 `@` 或已有子域名；提供“添加主域名…”“添加子域名…”的内联子表单，返回后自动选中。
- 尚未成功发布或没有可用运行端点的部署允许保存绑定草稿，不能直接显示已绑定生效；给出“前往发布”操作并保留选择。
- 选中部署后服务器自动确定，不能再独立选择另一个服务器而形成不一致配置。
- 已绑定其他部署的域名显示当前目标；选择后进入“迁移绑定”，不能静默覆盖。

### 第二步：检测并推荐

自动只读检查目标服务器、入口代理和服务端口，提供：

- 后端服务：单容器或 Compose service。
- 容器端口、上游协议、实际宿主机地址与端口。
- 推荐理由，例如“发现 api 服务映射 18080 → 3000，已返回 HTTP 响应”。
- 入口状态、HTTPS 前提和预计变更；已有外部代理占用时提供明确接入指引。

唯一明确的候选自动选中，多服务/多端口时用户选择；无法确认时允许填写目标容器端口并重新检测，不按框架默认值自动生效。优先复用当前端口，只有缺失映射时才规划端口分配与重建。

### 第三步：DNS 与变更预览

展示“完整域名 → 入口服务器 → 后端服务”的关系，并列出待执行变更和以下 DNS 信息：

| 信息 | 展示方式 |
| --- | --- |
| 记录类型 | 按目标给出 A、必要时 AAAA；子域名在存在明确且稳定的入口主机名时可建议 CNAME |
| 主机记录 | 根域名为 `@`，子域名为其前缀，同时展示完整名称，便于适配不同 DNS 控制台 |
| 预期目标 | 明确的公网入口地址或名称，不使用 SSH 内网地址或 `IP:端口` |
| 当前查询结果 | 实际记录、查询时间、与预期差异；未查询成功时显示未知 |
| 下一步 | 阿里云模式可编辑记录并“保存到阿里云”；外部手动模式提供复制记录；两者均可重新检查 |

默认开启 HTTPS，证书来源为受管入口自动签发。首期根域名优先建议 A/AAAA，不默认给出依赖服务商特性的根域名 CNAME。已存在 CNAME 或其他冲突记录时提示需要核对，不能机械要求追加 A 记录。可展示相关 TXT/CAA 等诊断，但不把域名页变成全部 DNS 记录编辑器。

底部操作为“返回”“保存草稿”“应用绑定”。未满足执行条件时说明缺少什么并提供具体动作；需要容器重建时，在应用预览中明确停机影响及恢复计划。

DNS 未就绪时默认保存草稿。阿里云模式可在应用内编辑、预览并提交建议记录，或在联合绑定计划中明确包含 DNS 变更；外部手动模式由用户修改记录后“重新检查”。API 保存与公开解析生效分开呈现；联合任务先准备目标入口，再按计划改 DNS，最后检查解析与访问。表单打开时可以有限自动刷新并标记倒计时；关闭后停止，不后台无限轮询。与之前状态不同或计划过期时重新生成预览，不自动提交。

### 第四步：执行与结果

“应用绑定”创建 Job，同 Sheet 展示探测、配置校验、代理应用、证书等待和访问检查阶段；关闭 Sheet 不取消后台 Job，卡片和操作记录可再次进入。需要取消时显式操作，显示实际已应用与恢复结果。

域名页、部署页和服务器关联信息同时读取同一个绑定 ID。只有已核对实际配置，且相应 DNS、TLS、后端与访问检查达到条件，才显示“可访问”；始终保留检查位置和时间。

## 5. 根域名与子域名的独立行为

示例规划：

| 完整域名 | 目标 | 行为 |
| --- | --- | --- |
| `example.com` | 官网部署 / 服务器 A / 容器 3000 | 使用服务器 A 的 80/443，反向代理到其实际后端 |
| `www.example.com` | 官网部署 / 服务器 A / 容器 3000 | 单独创建绑定与证书覆盖；访问与根域名相同站点，不自动重定向 |
| `api.example.com` | API 部署 / 服务器 B / 容器 8080 | 使用服务器 B 的入口及解析配置 |
| `admin.example.com` | 未绑定 | 只作为资产存在，不计为访问故障 |

多个域名绑定同一部署时复用其后端端口，不为每个域名重复创建容器、重建应用或分配端口。根域名未解析或未绑定时，子域名仍按自己的配置判断状态。

## 6. 状态、诊断与下一步

完整状态分为管理记录、绑定操作、DNS、入口、TLS 和后端几个维度；表格只汇总当前最需处理的一项，详情展示所有维度。

| 展示状态 | 触发情况 | 主操作 |
| --- | --- | --- |
| 未绑定 | 有域名记录，无绑定意图 | 绑定部署 |
| 待发布 | 草稿所选部署无可用运行端点 | 前往部署发布 |
| DNS 待配置 / 解析不匹配 | 预期入口已知，查询结果缺失或不同 | 配置解析（阿里云）/ 查看指引（外部手动） |
| 已提交，等待解析生效 | API 回读已确认记录，公开解析尚未一致 | 重新检查 |
| 入口冲突 / 需接入现有代理 | 80/443 或受管配置冲突 | 查看处理方案 |
| 待应用 | 草稿条件满足，尚未执行 | 预览并应用 |
| 配置中 / 证书申请中 | Job 正在对应阶段 | 查看任务 |
| 可访问 | 当前检查验证访问满足条件 | 打开网站 |
| 后端异常 / 证书异常 / 访问异常 | 对应检查失败 | 查看诊断并重试检查 |
| 状态未知 | 服务器断连、查询失败或状态过期 | 重新检查 |
| 迁移中 / 解绑中 / 需要恢复 | 正在变更，或恢复未完成 | 查看任务或恢复计划 |

优先展示正在执行的操作，再展示未知或异常，最后展示正常状态；根域名分组汇总异常数量，但保留每个子域名状态。查询缓存不能当成新检查；DNS 传播无法给出准确完成倒计时。HTTP 有响应和业务健康分开判断，401/404 不直接显示业务正常。

“刷新/检查”只读；“应用/重试变更/解绑”会写入服务器，两者的按钮文字和任务记录须明确区分。

## 7. 编辑、迁移、解绑与删除

### 修改目标与迁移

同域名更换部署或服务器时，显示旧目标、新目标、DNS 变更和影响。新入口先准备并验证，人工 DNS 切换后确认端到端访问，再清理旧路由。两个入口只允许在同一次迁移任务中临时共存，配置仍指向一个期望生效目标。

保留旧目标、原始解析观察值和操作阶段；DNS 手工模式下，不能声称已替用户回滚解析。失败时展示已恢复的代理状态和仍需用户恢复的 DNS 项。迁移期间旧访问状态与新目标验证结果分别显示，不能过早把旧路由当成垃圾清理。

### 解绑部署

确认内容列出完整域名和当前目标，说明将移除 iDeploy 受管路由、保留部署与域名资产，DNS 手工记录不会被自动删除。远端解绑成功后再完成本地状态变更；远端不可达时保留关联并显示待处理，不能直接清空 UI。

### 移除子域名与主域名

- 已绑定子域名先解绑，完成后可移除本地资产；未绑定子域名可直接移除并说明仅删除本地记录。
- 根域名 `@` 行始终属于主域名，可以解绑但不能单独删除。
- 主域名有子域名、根域名绑定或未完成任务时，移除操作展示阻止原因及逐项处理入口；首期不做一键级联远端清理。
- 移除本地记录不会删除服务商处已有 DNS，不使用“域名已注销”等文案。
- 删除部署或服务器时检测其域名关联，并链接到清理/迁移流程，避免悬空绑定。

## 8. 与其他页面协同

| 页面 | 入口与职责 |
| --- | --- |
| 域名 | 主域名资产、根域名/子域名、DNS 指引、访问详情和操作历史的主要管理入口 |
| 部署 | “域名与访问”卡片显示该部署的全部绑定；“绑定域名”打开统一流程；“管理域名”定位域名页对应主域名与访问项 |
| 发布结果 | 发布成功后提供“绑定域名”；已绑定时显示保持的地址，异步检查结果单独呈现，不重新创建绑定 |
| 服务器 | 显示入口代理状态和该服务器承载的域名；点击可定位域名详情，入口公共参数仅在服务器入口配置中维护 |
| 总览/任务 | 使用现有 Job 机制展示操作，点击定位具体域名；域名异常不篡改应用发布记录 |

跨页定位传递主域名 ID、访问项 ID、来源部署 ID；返回保留原选择。异步结果须校验对象 ID，防止切换主域名后显示上一个对象的数据。创建、保存和执行操作结束后刷新受影响记录，不让完整 DNS/网络检查阻塞全局刷新。

## 9. 数据与接口边界

在技术方案基础上增加两类域名资产，所有完整域名使用相同的规范化和唯一性校验：

- `domains`：规范化主域名、显示名称、备注、DNS 管理模式和时间；服务器不作为主域名必填字段。
- `domain_hosts`：主域名 ID、主机标签（根域名用 `@`）、完整域名、备注；固定根域名行与主域名同事务创建，完整域名全局唯一。
- 绑定关联 `domain_host_id`，保留期望目标与已应用目标、配置版本及迁移操作；一个访问项首期只有一份当前绑定配置，历史变更单独记录。
- DNS 预期记录来自当前绑定计划，DNS 实际结果属于带时间的观察快照；不能合并为一个容易误认为已写入服务商的字段。

新增 `ListDomains`、`CreateDomain`、`UpdateDomain`、`DeleteDomain`、`ListDomainHosts`、`CreateDomainHost`、`UpdateDomainHost`、`DeleteDomainHost`、`InspectDomainDNS` 等资产/查询接口，复用技术方案中的发现、规划、应用、检查与解绑接口。Go Runtime 统一处理归属、引用保护和规范化；Native Bridge、CLI、MCP 使用同一规则。

阿里云和 Cloudflare DNS Provider 已接入记录编辑；主域名选择对应连接。实际权威 NS 的自动核验、差异预览、记录变更与绑定的联合任务仍属于后续目标。当前写入前读取远端记录并使用服务商记录 ID 与更新时间核对；API 超时需刷新记录对账。界面不将“API 手动编辑”混称为全自动托管。

## 10. 实施顺序与交互验收

1. **域名资产页**：侧栏入口、主域名 CRUD、固定根域名行、子域名 CRUD、搜索/筛选、只读 DNS 检测和空态。此阶段清楚标注绑定能力尚未交付。
2. **绑定闭环与阿里云接入**：连接授权、导入域名、应用内解析记录查询/编辑、统一表单、端点推荐、受管入口和 HTTPS、Job 状态、解绑；接通部署页和服务器页定位。
3. **变更与恢复**：自动端口分配/重建、跨服务器迁移、配置快照、失败恢复与数据引用保护的完整验证。
4. **扩展**：现有代理接入、其他 DNS Provider、更深子域名、重定向和高级路由。

验收必须覆盖：

- 添加主域名后无需绑定根域名即可添加并使用子域名；根域名异常不阻断独立子域名。
- 不同子域名可绑定不同服务器，同部署多个域名复用实际后端端口。
- 主域名/子域名重复、误填 URL、粘贴完整域名、IDNA 和公共后缀归属处理清晰。
- 多端口和 Compose 多服务无静默误选；未知和缓存不会显示为正常。
- DNS 未配置、入口占用、证书申请失败、应用成功但公网不可达均有准确状态和下一步。
- 两个页面编辑同一绑定能检测版本冲突；切换选中对象不会混入旧请求结果。
- 阿里云只读权限、凭据失效、API 保存失败、提交超时、重复提交、外部修改、TTL/线路受限均有明确反馈；API 成功不直接标为公网访问正常。
- 关闭 Sheet 不取消 Job，删除资源不会留下无法追踪的路由，迁移不会提前破坏旧访问。
- 在 1000×670pt 最小窗口和更大窗口下，表单和操作可达；Tab、Return、Escape、焦点恢复、VoiceOver 状态文字及错误定位可用。

该方案确认后再进入 SwiftUI 与 Go 实现，沿用仓库构建和测试要求；本次未运行应用构建或远端验证。
