# 设计原则

1. **先保持当前产品识别。** 深绿导航、浅绿工作区、白色/淡绿卡片、绿色主操作与窄列表栏构成当前 iDeploy。新增页面沿用这套结构和层级。
2. **信息优先。** 页面标题说明当前位置；列表显示名称及一行关键上下文；详情首先呈现对象名、状态和主操作，再给出配置、运行信息与历史。
3. **原生行为优先。** 控件继续使用 macOS 的 Button、Picker、Form、Menu、Sheet、确认对话框与菜单命令。定制视觉不能吞掉键盘焦点或 VoiceOver 名称。
4. **颜色有角色。** 森林绿代表品牌、可执行主操作和选中；红/橙代表错误和警告。状态文字始终保留，不能只用颜色传义。
5. **桌面密度。** 列表行、表单和详情按鼠标/键盘使用设计，不移入 iOS 式大卡片、底部导航或全屏步骤流。
6. **只显示真实数据。** 分类标签必须对应实际字段；当前部署模型没有 `production/staging` 环境名，不得从服务器名猜测或将设计稿示例当业务值。
7. **渐进改进。** 当前固定浅色、手工分栏和小字号属于已知限制。改进它们需单独验证各页面，不得在编写规范时悄悄改变业务界面或操作语义。
