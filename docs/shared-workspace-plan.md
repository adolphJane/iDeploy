# iDeploy 共享工作区服务方案

状态：开发中。已接入首次迁移、SSH 隧道配对、客户端加密凭据、增量同步、修订号冲突处理、发布租约和新任务的脱敏摘要。设置页可预览迁移、加入设备、同步、查看冲突及撤销设备。当前尚未完成双 Mac 与 MySQL 端到端验收；请勿将该构建视为已验证的生产级跨设备同步。

## 目标与部署结构

用户在「设置 → 共享工作区」选择已连接服务器，预检并预览变更后部署 iDeploy Server 和专用 PostgreSQL；在第二台 Mac 添加服务地址并登录，即可看到同一工作区的配置、发布历史和任务状态。保留单机模式。服务端与现有服务器 Agent 是两个组件：Server 负责工作区、认证和任务协调；Agent 在目标服务器执行受限操作。

首版采用单台 Server、单个工作区和单个管理员，可登记多台设备。Compose 固定镜像版本和摘要，数据库使用独立持久卷和独立账号，不对公网发布数据库端口；应用服务默认仅监听服务器本地地址，由用户配置受信任的 HTTPS 入口或通过 SSH 隧道连接。部署预检检查架构、Docker Compose、磁盘、端口、已有入口和镜像可用性；展示将创建的容器、卷、端口和升级前备份位置。不能覆盖现有服务或自动接管 Nginx。安装、更新、卸载分别是独立操作；默认卸载仅移除服务容器，保留数据卷，彻底删除数据另行确认。

## 数据与设备边界

| 数据 | 共享工作区 | 设备本地 |
| --- | --- | --- |
| 项目、Git 来源、构建配置、部署、服务器、仓库、数据库和域名配置 | 共享稳定 ID、配置与版本 | 本地项目目录、文件访问授权、SSH 私钥路径和工具路径 |
| 发布历史和任务 | 共享发布记录及脱敏任务摘要 | 历史任务日志、本地构建缓存、工作目录和临时文件 |
| 密码、Token、SSH 私钥口令、部署秘密 | 客户端加密后保存的密文及共享服务持有的密钥 | 本机钥匙串；SSH 私钥文件不上传 |
| 状态与设置 | 服务端维护共享资源变更版本 | 窗口偏好、主机指纹信任和本地探测结果 |

当前 SQLite 中的 `credential_ref` 只是本机钥匙串引用，不作为共享资源上传。迁移时读取本机钥匙串，在客户端使用共享服务提供的密钥加密，再单独上传密文；新设备配对后将凭据写入自身的 Keychain。普通环境变量、构建参数、DNS AccessKey ID 和发布清单也按敏感字段处理。仓库 URL 中含认证、查询参数或片段时阻止迁移。

## 首次部署和迁移

1. 选择服务器，检查 SSH 身份、磁盘、架构、容器、端口、持久卷及 HTTPS 接入。展示部署计划和已有工作负载；由用户启动部署。
2. 安装固定版本，生成安装凭据并通过受保护的通道初始化；数据库凭据不出现在命令行、日志或 Compose 明文环境文件。健康检查包含数据库迁移和版本兼容性。失败保留诊断和恢复路径。
3. 创建设备登录凭据，设备凭据存入 Keychain。新增设备通过短期一次性配对码登录；支持查看设备和撤销。
4. 在本机生成只读迁移预览：按资源类型显示数量、冲突、不可移植路径和凭据缺失。初次导入使用批次 ID、稳定资源 ID 和服务端事务，重复提交返回原结果；保留原本地数据，禁止自动覆盖已有工作区。
5. 首次仅允许导入到空工作区；已有数据时显示冲突供用户逐项处理。导入完成后对账数量和引用，再由用户切换到共享模式。切换可返回单机模式，但需说明之后两边的数据不会自动合并。

## 修改、离线与任务

服务端是共享数据的唯一写入源。读取可使用本地缓存；离线时只读并显示最后同步时间，禁止排队执行部署或静默覆盖配置。每条记录携带服务端修订号；更新和删除携带预期修订号，冲突时返回当前版本并让用户重新选择。删除记录使用可同步的删除标记和保留期，避免离线设备恢复后复活旧数据。列表分页、增量游标及完整重建有明确版本边界；过期游标触发完整重同步。

发布、回滚和远程写操作统一经 Server 创建持久化任务，以请求 ID 防重复；数据库事务确保发布记录、任务及资源锁一致，同一服务器保留当前串行约束。执行器领取任务使用租约、心跳和 fencing token，租约过期后先对账远端操作与制品状态，不盲目重复推送、部署或回滚。取消、失败、网络中断和重启均需显示可恢复状态。任务日志及错误需脱敏、限制大小并制定保留策略。

现有发布在发起 Mac 构建，本地路径不能被服务器直接访问。首版由发起设备使用本地钥匙串执行构建、推送和通过 Agent/受控 SSH 的远程部署；服务端协调任务并记录不可变镜像摘要。设备断线时任务标为等待设备或中断，不声称后台仍在执行。恢复必须对账已有制品和远端操作，不能重复覆盖版本。后续可增加服务器构建执行器：Git 项目由服务端按固定提交检出；本地项目需显式上传受限源码快照并处理忽略规则、大小与敏感文件。服务端独立执行还需要另行解决凭据授权。运行 Docker 构建的执行器属于高权限组件，隔离网络与权限，不能向普通客户端暴露 Docker socket 或任意命令接口。

## 连接、升级和恢复

所有远程请求要求身份认证、TLS 和服务端身份校验；记录关键配置与部署操作的审计信息，不记录凭据。客户端和 Server 握手 API、数据模型与能力版本；不兼容时阻止写入并提供升级提示。服务端升级先备份数据库和配置，再拉取校验镜像、运行兼容迁移、健康检查；失败保留备份和旧镜像，数据库发生不可逆迁移时禁止直接回滚旧程序，使用经过验证的恢复流程。

提供加密备份、导出、恢复与恢复演练，清晰说明备份包含的数据、密钥和保留时间。恢复到新服务器后应验证版本、完整性和设备授权，避免两个实例同时作为同一工作区的写入源。数据库与应用健康、磁盘用量、备份时间和任务队列在设置页可见；密钥丢失与服务器损坏的恢复能力必须在发布前验证。

## 开发顺序与验收

1. 提取存储和任务接口，梳理 SQLite 特有 SQL、事务与迁移；单机模式回归，完成威胁模型及执行边界。
2. 实现 Server、PostgreSQL 迁移、认证配对、版本握手和只读数据 API；验证权限隔离和连接失败。
3. 实现修订号写入、删除标记、冲突处理及首次迁移；验证中断、重复导入、对账和本地数据恢复。
4. 实现任务协调、租约和远端对账；验证双设备并发发布、断线、重启、取消、失败恢复及回滚。
5. 实现部署向导、状态、备份、升级和卸载；使用独立测试服务器验证，不改动已有入口和容器。
6. 验证双 Mac 新增、修改、删除、离线重连、设备撤销、不同本地路径、缺失凭据和日志脱敏。提供清晰的失败提示和操作文档，再开放共享模式。

以上是分阶段交付的完整目标；每阶段需达到对应验收后再进入下一阶段。具体监听地址、域名、凭据共享与部署服务器在实施和实际部署时由用户选择。

## 当前开发切片

`cmd/ideploy-server` 启动共享服务。`build/shared-server/compose.yaml` 在服务器本机 `127.0.0.1:8765` 暴露服务端口，PostgreSQL 不发布端口。启动前需在 `build/shared-server/secrets/` 安全创建 `postgres_password`、`database_url` 和 `server_token` 三个文件；这些文件已被 Git 忽略，令牌至少 32 个字符。`database_url` 指向 Compose 中的 `postgres` 服务。`GET /healthz` 检查数据库；`GET /v1/workspace` 需要 `Authorization: Bearer <token>`，返回 API 版本和工作区修订号。服务默认只提供 HTTP 本地入口，跨设备接入必须另行配置受信任 HTTPS 代理或 SSH 隧道。

`GET /v1/resources/{kind}` 返回指定类型资源及删除标记，首版每类最多 1000 项。`PUT /v1/resources/{kind}/{id}` 使用 `{"expectedRevision":0,"data":{...}}` 创建，后续写入必须提交已读取的修订号；`DELETE` 使用 `{"expectedRevision":N}` 保留删除标记。允许的类型为 project、deployment、server、registry、database、domain；服务限定每类字段，拒绝常见凭据字段和过大的文档。管理员令牌可通过 `POST /v1/devices` 登记设备并一次性获取设备令牌，`GET /v1/devices` 查看设备，`DELETE /v1/devices/{id}` 撤销设备。这些 API 当前只是协议基础，尚无完整结构校验、短期配对码和跨资源引用校验，不能直接开放给外部客户端。

当前实现还包括 `/v2/imports`、`/v2/changes`、`/v2/batches`、`/v2/vault`、`/v2/secrets`、`/v2/pairings` 和 `/v2/leases`。空工作区事务导入后校验数量与摘要，再切换共享模式。共享服务持有自动生成的凭据加密密钥，客户端通过已认证的 SSH 隧道获取并在本机 Keychain 缓存；无需主密码或恢复密钥。新设备须先保存可用于 SSH 隧道的服务器连接并确认主机指纹，再输入一次性配对码。SSH 私钥文件和本地源码不上传。共享服务器或其数据库被完全控制时，攻击者可能读取共享凭据。

已有远程 MySQL 时，可在「设置 → 共享服务」选择已连接服务器与 MySQL 连接，执行预检和部署。服务仅绑定服务器 `127.0.0.1:8765`，客户端通过 SSH 隧道接入。MySQL 需预先创建专用数据库与具备建表及读写权限的账号。默认要求可验证的 TLS 证书；对旧版 MySQL 自动生成证书可显式选择跳过证书身份验证，但仍保持 TLS 加密。共享服务升级前会把共享表结构和数据备份到本机 `~/Library/Application Support/iDeploy/backups/` 中权限为 0600 的 JSON 文件，并保留旧容器；健康检查失败时尝试恢复旧容器。手动部署可使用 `build/shared-server/compose.mysql.yaml` 和 `IDEPLOY_DB_*` 环境变量。

## 尚需验收

- 两台真实 Mac 与远程 MySQL 的完整新增、编辑、删除、冲突及离线重连测试尚未执行。
- 发布任务通过服务端租约互斥，但远端制品与任务断线后的自动对账仍需完成并实测。
- 旧版 SQLite 的普通环境变量、构建参数及发布清单可能本就含明文；迁移会在传输前加密这些字段，但本机静态数据的彻底迁出还需独立迁移。
- 设备撤销会阻止后续 API 访问；已在设备上解锁的本机缓存需要额外的密钥轮换机制才能失效。
