# 服务器现有服务的域名路由

在「域名 → 解析记录 → 服务绑定」中选择「服务器现有服务」，可将 A、AAAA 或 CNAME 记录对应的完整域名转发到服务器上的 HTTP 服务。选择服务器后可扫描现有 Nginx 路由，查看域名、转发目标、推测的 Docker 服务以及 HTTPS 证书路径。扫描只读取远端配置，不修改 DNS 或 Nginx。

扫描还会列出 Docker 已发布的 TCP 端口，可直接选用 Harbor 等服务的候选端口；端口列表不判断上游协议，选择后必须通过 HTTP 预检。配置目标 IP、HTTP 端口并保存草稿后，先运行预检。预检会探测后端 HTTP 响应，检查现有入口及配置版本，并生成将写入的 Nginx 路由预览。启用 HTTPS 时，填写 Nginx 容器内已有的证书和私钥路径；预检验证文件可读、证书覆盖目标域名且处于有效期。没有匹配证书时保持 HTTP，待服务器上准备证书后再应用 HTTPS 路由。应用任务会备份主配置、执行 `nginx -t`、重载并检查 HTTP/HTTPS 路由；失败会尝试恢复备份。

只有使用 host 网络、将主配置文件绑定到宿主机且当前 SSH 用户可写的单个 Nginx 容器，才支持自动应用。已有手工声明的同名路由会阻止接管；扫描结果可用于核对服务，应用不会覆盖手工配置。当前不自动签发证书，也不修改阿里云 DNS。DNS 检查确认公开解析结果，HTTPS 检查验证证书和路由标记；SSH 连接地址可能与公网入口不同，因此不会直接当成 DNS 期望地址。

对 iDeploy 已发布的部署，在「配置访问目标」中，容器端口旁的 HTTP 指入口到应用的后端协议；域名 HTTPS 单独配置。选择现有 Nginx 入口后可启用域名 HTTPS 并复用证书；选择受管 Caddy 入口时由 Caddy 自动处理域名 HTTPS。保存草稿后须重新预检并应用，保存本身不会改动远端配置。
